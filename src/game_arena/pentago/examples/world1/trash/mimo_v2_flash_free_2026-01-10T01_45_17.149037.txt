My strategy is to implement a short-term minimax search with alpha-beta pruning. This approach considers not only the placement of a marble but also the subsequent rotation of a quadrant, which is critical in Pentago.

1.  **Board Representation**: I will use a single integer (bitboard) for each player to represent the 6x6 grid. This allows for very fast move generation and win checking using bitwise operations.
2.  **Move Generation**: I will iterate over all empty cells (placement) and all 8 possible rotations (4 quadrants × 2 directions). This results in a branching factor of roughly 36 × 8 = 288 moves.
3.  **Evaluation**: I will implement a win check. If a move results in the player winning, it is immediately selected. If it allows the opponent to win, it is avoided.
4.  **Search**: I will use a 2-ply search (Current player's move -> Opponent's response). I will select the move that minimizes the maximum damage the opponent can do (Minimax). To ensure the code runs within the 1-second limit while maintaining safety, I will limit the search depth and use a simple heuristic (counting potential 3-in-a-row and 4-in-a-row threats) to evaluate non-terminal board states.
5.  **Safety**: To guarantee legality even in edge cases, I will include a fallback mechanism that returns a valid move if the search fails or if no move is found.

        return bin(board).count('1')

                            if opp_can_win: break
