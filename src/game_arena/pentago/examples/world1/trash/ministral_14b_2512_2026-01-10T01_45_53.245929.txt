### Thinking Process

The goal is to implement a move-selection policy for Pentago that always returns a legal move. Pentago is a complex game with both placement and rotation components, so the policy needs to consider both aspects. Here's the approach I'll take:

1. **Legal Move Generation**:
   - First, generate all possible legal moves. A legal move consists of:
     - Placing a marble in any empty cell (1-6, 1-6).
     - Choosing a quadrant (0-3) and a rotation direction (L or R).
   - Ensure that the placement and rotation are valid (e.g., the quadrant exists, the rotation direction is valid).

2. **Move Evaluation**:
   - For each legal move, simulate the move (placement + rotation) and check if it results in a win for the current player.
   - If no immediate win is possible, prioritize moves that block the opponent from winning on their next turn.
   - If neither wins are possible, choose a move that maximizes some heuristic (e.g., center control, symmetry, or randomness).

3. **Heuristics**:
   - **Immediate Win**: If a move leads to a win, choose it.
   - **Block Opponent**: If the opponent can win on their next turn, block them.
   - **Center Control**: Prefer placing marbles in the center (rows 3-4, cols 3-4) as they are more versatile.
   - **Randomness**: If no clear strategy, choose a random legal move.

4. **Implementation**:
   - Use helper functions to:
     - Check if a move is legal.
     - Simulate the move (placement + rotation).
     - Check for a win after the move.
   - Iterate through all possible moves, evaluate them, and pick the best one.

### Key Challenges
- **Rotation Simulation**: Correctly rotating a 3x3 quadrant (both players' marbles) in the specified direction.
- **Win Check**: Efficiently checking for 5-in-a-row after the move (horizontal, vertical, diagonal).
- **Performance**: The policy must run within 1 second, so brute-forcing all moves is feasible (6*6*4*2 = 288 possible moves per turn).

def rotate_quadrant(you_board, opponent_board, quad, direction):
    # Extract the quadrant
    if quad == 0:  # top-left
        rows = slice(0, 3)
        cols = slice(0, 3)
    elif quad == 1:  # top-right
        rows = slice(0, 3)
        cols = slice(3, 6)
    elif quad == 2:  # bottom-left
        rows = slice(3, 6)
        cols = slice(0, 3)
    else:  # bottom-right
        rows = slice(3, 6)
        cols = slice(3, 6)

    quadrant_you = you_board[rows, cols]
    quadrant_opponent = opponent_board[rows, cols]

    if direction == 'L':
        # Rotate 90 degrees anticlockwise
        rotated_you = np.rot90(quadrant_you, k=1)
        rotated_opponent = np.rot90(quadrant_opponent, k=1)
    else:  # 'R'
        # Rotate 90 degrees clockwise
        rotated_you = np.rot90(quadrant_you, k=-1)
        rotated_opponent = np.rot90(quadrant_opponent, k=-1)

    # Place the rotated quadrant back
    you_board[rows, cols] = rotated_you
    opponent_board[rows, cols] = rotated_opponent

    return you_board, opponent_board

### Explanation
1. **Legal Move Generation**: The code first generates all possible legal moves by iterating over all empty cells and all possible quadrant rotations.
2. **Immediate Win Check**: For each move, it simulates the placement and rotation, then checks if the move results in a win for the current player. If so, it returns that move immediately.
3. **Block Opponent**: If no immediate win is found, the code checks if the opponent can win on their next turn. If so, it blocks the opponent by choosing a move that prevents their win.
4. **Center Control**: If no immediate win or block is found, the code prefers moves that place marbles in the center of the board (rows 3-4, cols 3-4) for better strategic control.
5. **Fallback**: If no clear strategy is found, the code randomly selects a legal move.

This approach ensures that the policy always returns a legal move while prioritizing winning strategies and blocking the opponent.
