## Strategy Analysis

1. **Game Flow**: Players alternate turns (left/right based on `control`). Each player presses a button, then must `tick` to advance.

2. **State Patterns**:
   - When `["played", role]` exists → the only legal move is `tick`
   - Otherwise → must press a button (a, b, or c)

3. **Button Selection Pattern**: By analyzing all examples, the button choice follows the step number:
   - Step % 3 == 1 → `a(role)`
   - Step % 3 == 2 → `b(role)`  
   - Step % 3 == 0 → `c(role)`

   Verification:
   - Step 1: a(left) ✓
   - Step 2: b(right) ✓
   - Step 6: c(right) ✓ (6 % 3 = 0)
   - Step 7: a(left) ✓ (7 % 3 = 1)
   - Step 11: b(left) ✓ (11 % 3 = 2)
   - Step 12: c(right) ✓ (12 % 3 = 0)

The policy follows this deterministic sequence that appears to be the intended gameplay for this "parallel buttons and lights" coordination game.

def policy(state: list[list[object]], role: str) -> str:
    """
    Policy for parallelbuttonsandlights game.
    
    Strategy:
    - If we just played (played, role exists), return 'tick'
    - Otherwise, select button based on step number (cycling a, b, c)
    """
    # Check if we just played - if so, tick to advance
    for prop in state:
        if len(prop) >= 2 and prop[0] == "played" and prop[1] == role:
            return "tick"
    
    # Get the step number from state
    step = 1
    for prop in state:
        if len(prop) >= 2 and prop[0] == "step":
            try:
                step = int(prop[1])
            except (ValueError, TypeError):
                step = 1
            break
    
    # Choose button based on step (cycling a, b, c)
    # Pattern: step % 3 == 1 -> a, == 2 -> b, == 0 -> c
    if step % 3 == 1:
        return f"a({role})"
    elif step % 3 == 2:
        return f"b({role})"
    else:
        return f"c({role})"
