The game is Clobber, a combinatorial game played on a grid. The board size is 5x6 (30 squares). The game is played with two players, "you" and "opponent", represented by binary grids. A move consists of taking one of your pieces and moving it orthogonally to an adjacent square occupied by an opponent's piece, removing the opponent's piece. The first player unable to move loses.

The game Clobber is known to be an impartial game (in this specific input format, the board is symmetric with respect to the definition of the players' pieces, though the specific positions might differ). The game ends when a player cannot move. Since there are no draws (a player must eventually run out of pieces or mobility), the game is a zero-sum game with values $\{1, -1\}$ (Win/Loss).

Because the board is small (30 cells), the total number of states is at most $3^{30} \approx 2 \times 10^{14}$, which is too large for full retrograde analysis. However, the "density" of the game implies that typically players have few legal moves (often < 5). This suggests that a search algorithm like Minimax with Alpha-Beta pruning, potentially using a transposition table, can search the game tree to sufficient depth to find optimal moves.

Since we are competing in a gaming arena, we need a strategy that is:
1.  **Fast**: Must execute within 1 second.
2.  **Optimal**: Should find the best move if the game tree is shallow enough, or a very good move if it is deep.

**Strategy:**
1.  **State Hashing**: We will represent the board state as a 64-bit integer (Zobrist hashing) to support a transposition table.
2.  **Minimax with Alpha-Beta Pruning**: We will use a recursive search. Since the game is deterministic and perfect information, Minimax is appropriate.
3.  **Transposition Table**: We will store visited states to avoid re-computation. This is critical for efficiency.
4.  **Iterative Deepening**: We will search depth 1, then depth 2, etc., until time runs out. This ensures we always have a move ready.
5.  **Simple Evaluation**: If we reach the depth limit or a terminal state, we use a simple heuristic. A simple win/loss heuristic (1 for win, -1 for loss, 0 for draw if possible) is best. Since the game is finite and acyclic, we don't strictly need a depth-based heuristic, but the depth limit requires one. However, for Clobber, the terminal state is simply "no moves left".             if time.time() - start_time > 0.85:
```python
                break
            
            current_best = None
            alpha = -float('inf')
            beta = float('inf')
            
            for move in scored_root:
                # Unpack: cost, r, c, d, nm, no
                r, c, d, nm, no = move[1], move[2], move[3], move[4], move[5]
                
                # Search with depth-1 (opponent's turn)
                val = -search(no, nm, depth - 1, -beta, -alpha, start_time)
                
                if val > alpha:
                    alpha = val
                    current_best = (r, c, d)
                    if alpha >= 1.0: # Found a guaranteed win
                        break
                
                if alpha >= beta:
                    break
            
            if current_best:
                best_move = current_best
            
            # If we found a win, stop deeper search
            if alpha >= 1.0:
                break
            
            depth += 1
            if depth > 25: # Safety cap
                break
    else:
        # Should not be called when no moves exist, but fail-safe
        return "0,0,U"

    # 7. Return Result
    if best_move:
        return f"{best_move[0]},{best_move[1]},{best_move[2]}"
    
    # Fallback to first sorted move if something goes wrong
    return f"{scored_root[0][1]},{scored_root[0][2]},{scored_root[0][3]}"
```
