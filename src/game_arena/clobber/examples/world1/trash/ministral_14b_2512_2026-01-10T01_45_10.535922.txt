### Thinking Process:

**Understanding the Game Clobber:**
Clobber is a two-player abstract strategy game played on a 5x6 grid. Players take turns moving their pieces to capture opponent pieces by moving orthogonally (up, down, left, right) onto an opponent's piece. The opponent's piece is removed, and the moving piece takes its place. The player who cannot make a legal move loses.

**Objective:**
The goal is to implement a move-selection policy that always returns a legal move. The policy should be simple but effective, ensuring that the AI doesn't get stuck and always makes a valid move.

**Approach:**
1. **Legal Moves Generation:** First, we need to identify all legal moves available to the current player. A legal move is defined as moving one of your pieces orthogonally onto an opponent's piece.
2. **Move Selection:** Since the problem doesn't specify a complex strategy (like minimax or alpha-beta pruning), we can use a simple heuristic to select a move. One common heuristic is to prioritize moves that capture opponent pieces in a way that maximizes the number of future moves or minimizes the opponent's options. However, for simplicity, we can just pick the first legal move found (or a random one if multiple exist).

**Implementation Steps:**
1. Iterate over all your pieces on the board.
2. For each piece, check its four possible orthogonal directions (up, down, left, right).
3. For each direction, check if the destination cell is within bounds and contains an opponent's piece.
4. If such a move is found, return it immediately (or collect all legal moves and choose one based on a simple heuristic).
5. Ensure that the move is always legal and that the function never returns an invalid move.

**Heuristic Choice:**
For simplicity, we can choose the first legal move found in a row-major order (left to right, top to bottom). This ensures determinism and simplicity.

**Edge Cases:**
- The function is guaranteed to be called only when there is at least one legal move, so we don't need to handle cases where no moves are available.
- The board is always valid (no overlapping pieces, etc.).

**Optimization:**
- Use nested loops to iterate over the board and check for legal moves.
- For each piece, check the four directions in a fixed order (e.g., up, right, down, left) to ensure consistent move selection.

### Python Implementation:

```python
def policy(you: list[int], opponent: list[int]) -> str:
    # Iterate over each cell in the board
    for row in range(5):
        for col in range(6):
            if you[row][col] == 1:  # If it's your piece
                # Check all four directions
                directions = [('U', -1, 0), ('R', 0, 1), ('D', 1, 0), ('L', 0, -1)]
                for dir_char, dr, dc in directions:
                    new_row, new_col = row + dr, col + dc
                    # Check if the new position is within bounds and has opponent's piece
                    if 0 <= new_row < 5 and 0 <= new_col < 6:
                        if opponent[new_row][new_col] == 1:
                            return f"{row},{col},{dir_char}"
    # This line is theoretically unreachable due to problem constraints
    return "0,0,U"  # Fallback (should never happen)
```

### Explanation:
1. The function iterates over each cell in the 5x6 grid.
2. For each cell that contains your piece (`you[row][col] == 1`), it checks the four possible directions (up, right, down, left).
3. For each direction, it calculates the new position (`new_row`, `new_col`) and checks if it is within bounds and contains an opponent's piece (`opponent[new_row][new_col] == 1`).
4. The first valid move found is returned in the format `'row,col,dir'`.
5. The fallback return is a placeholder and should never be reached due to the problem's guarantee that at least one legal move exists.

This approach ensures that the policy is simple, deterministic, and always returns a legal move. The move selection is based on the first valid move found in row-major order, which is efficient and easy to understand.
