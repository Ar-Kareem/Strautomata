The game is Clobber on a $5 \times 6$ board.
Goal: Implement a move-selection policy that plays optimally (or strongly).
Given the constraints (state size small, 1 second per move), we can use **Minimax with Alpha-Beta pruning** and **Zobrist Hashing with a Transposition Table**.
Since I don't have access to a pre-computed endgame database, I will implement a search engine that solves the game from the current state.
The game is finite and deterministic, so perfect play is possible within the time limit for many states. I will use iterative deepening to maximize the depth searched within 0.9 seconds.

**Strategy:**
1.  **Representation**: Flatten the $5 \times 6$ board into bitboards (90 bits total). Since 128-bit integers are native in Python, we can represent `my_pieces` and `opp_pieces` as integers.
2.  **Move Generation**: Precompute direction offsets for all 90 cells. Generate moves by iterating over set bits of `my_pieces`, checking neighbors in `opp_pieces`.
3.  **Search**:
    -   **Iterative Deepening**: Start depth 1, increase until time runs out.
    -   **Alpha-Beta Pruning**: Minimize worst-case outcome.
    -   **Transposition Table**: Cache board states (Zobrist hash) to avoid re-evaluating branches.
    -   **Ordering**: Heuristic to check captures that remove opponent pieces capable of capturing us (reciprocal threats) first.
4.  **Evaluation**: 
    -   If a terminal state (no moves), return -infinity (losing) or +infinity (winning).
    -   If depth is 0, use a static heuristic: material difference + mobility + connectivity.

                    Neighbors[idx].append(n_idx)
                    Dir_Idx[idx].append(d)

        return val

        score = (cnt_me - cnt_opp) * 1000 + my_mobility
