Pour resolver ce problème, nous devons développer une fonction de politique pour un champ de Kalah qui sélectionne la meilleure option de mouvement en fonction de l'état actuel du jeu. La fonction doit prioriser les mouvements qui entraînent des captures suivies par ceux qui aboutissent à une possibilité de mouvement supplémentaire.

### Approche
1. **Simulation des déplacements** : Pour chaque étape Possible (non vide) dans la pochette du joueur, simulez le mouvement de distribution de pierres:
   Les pierres sont distribuées dans l'ordre inverse horaire à partir du prochain trou jusqu'au magasin du joueur, puis aux trous du joueur adverse, et enfin retournent aux trous du joueur.
   Suivez les pierres posées pendant la simulation et déterminez la position finale de la dernière pierre. 
2. **Détection de capture** : Si la dernière pierre tombe dans une maison du joueur qui était vide au début du mouvement, capturez les pierres de cette maison et de la maison opposée du concurrent.
3. **Critères de classement** : Les mouvements sont rangés selon :
   Nombre de pierres capturées (les plus élevées prioritaires). 
   Si les captures sont égales, les mouvements qui donnent des mouvements supplémentaires (mettre les pierres dans le magasin du joueur) sont privilégiés. 
4. **Sélection du Mouvement** : Sélectionnez le premier mouvement parmi les mouvements les mieux classés en fonction des critères ci-dessus.

### Solution Code
```python
def policy(you, opponent):
    best_moves = []
    for i in range(6):
        if you[i] == 0:
            continue
        
        sim_you = list(you)
        sim_opponent = list(opponent)
        s = sim_you[i]
        sim_you[i] = 0
        current_pos = i + 1  # starting position (after picking i)
        
        for _ in range(s):
            if current_pos >= 13:  # opponent's store (pos 13) is invalid
                current_pos = 0
                continue
            pos = current_pos
            if pos < 6:
                sim_you[pos] += 1
            elif pos == 6:
                sim_you[6] += 1
            else:
                op_pos = pos - 7
                sim_opponent[op_pos] += 1
            current_pos += 1
        
        last_pos = (i + s) % 13
        extra_move = (last_pos == 6)
        
        captured_stones = 0
        if 0 <= last_pos <= 5:
            original_you = you[last_pos]
            if original_you == 0:
                opp_pos = 5 - last_pos
                if sim_opponent[opp_pos] > 0:
                    captured = sim_you[last_pos] + sim_opponent[opp_pos]
                    captured_stones = captured
                    sim_you[last_pos] = 0
                    sim_opponent[opp_pos] = 0
                    sim_you[6] += captured
        
        captured = captured_stones
        extra = extra_move
        best_moves.append((i, captured, extra))
    
    best_moves.sort(key=lambda x: (-x[1], -x[2]))
    return best_moves[0][0]
```

### Explication
1. **Simulation de déplacements** : Pour chaque mouvement possible, la fonction simule la distribution des pierres en partant de la position suivante après l'index choisi. Les pierres sont réparties en boucle autour du tableau en sautant la stockage de l'adversaire.
2. **Capture Detection** : Après avoir distribué les pierres, la position finale est vérifiée. Si elle atterrit dans un terrier du joueur qui était vide avant le mouvement, une capture a lieu. Les pierres capturées proviennent du terrier du joueur et de la maison opposée de l'adversaire.
3. **Critères de classement** : Les mouvements sont classés prioritairement en fonction du nombre de pierres capturées. Si le nombre de pierres capturées est égal, les mouvements qui donnent des coups supplémentaires (mejurer les pierres dans le magasin) sont privilégiés. Cela garantit que le mouvement sélectionné maximise les avantages immédiats et maintient l'avantage du mouvement.
