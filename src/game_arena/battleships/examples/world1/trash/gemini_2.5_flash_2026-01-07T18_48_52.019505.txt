            if is_horizontal:
                r = first_point[0] # All hits in segment are on this row
                min_c = min(s[1] for s in segment_sorted)
                max_c = max(s[1] for s in segment_sorted)

                if min_c - 1 >= 0 and board[r][min_c - 1] == 0:
                    current_segment_shots.append((r, min_c - 1))
                if max_c + 1 < 10 and board[r][max_c + 1] == 0:
                    current_segment_shots.append((r, max_c + 1))
            else: # Vertical or single point (handled above, but for safety in case of non-contiguous segment logic bug)
                c = first_point[1] # All hits in segment are on this column
                min_r = min(s[0] for s in segment_sorted)
                max_r = max(s[0] for s in segment_sorted)

                if min_r - 1 >= 0 and board[min_r - 1][c] == 0:
                    current_segment_shots.append((min_r - 1, c))
                if max_r + 1 < 10 and board[max_r + 1][c] == 0:
                    current_segment_shots.append((max_r + 1, c))
        
        # Add shots from this segment with their segment_len score
        for shot_coord in current_segment_shots:
            scored_potential_shots.append((segment_len, shot_coord))
            
    if scored_potential_shots:
        # Sort to prioritize longer segments, then pick a random one among top scores
        scored_potential_shots.sort(key=lambda x: x[0], reverse=True)

        top_shots = [s[1] for s in scored_potential_shots if s[0] == max_score]

**Final check on segment sorting and orientation:**
The segment finding loop populates `current_segment` with `(r, c)` tuples. If I `segments.append(sorted(current_segment))`, then when I iterate `segment in segments`, `segment[0]` and `segment[1]` (if it exists) will be correctly ordered. This makes the `is_horizontal` check reliable.

One edge case: if `board` changes such that a segment that was length 2 becomes length 1 (e.g. one part was sunk, or hit was part of another ship and somehow removed, which shouldn't happen with given rules).
My segment finding `_get_segment` implicitly handles this, as it just collects current `1`s. So `all_hits` is the current source of truth.

The "Should not happen" return `(0,0)` if no cells are left is okay. In practice, the game would end.

The strategy seems solid:
1.  Identify all contiguous 'hit' segments on the board.
2.  If segments exist, try to extend the longest ones first. If multiple longest segments, choose randomly. If a single-hit segment, try all 4 cardinal directions.
3.  If no segments are found or extended, switch to hunting using a checkerboard pattern. Alternate patterns if one is exhausted.
4.  If all cells are shot, return (0,0) as a fallback.

This logic makes sense for Battleship. It prioritizes sinking identified ships and then reverts to an efficient hunting pattern.
A `random.shuffle` on `_DIRECTIONS` in the single-hit case might make it less predictable/exploitable if an opponent could guess my pattern. Let's add that for single hits.

The random.shuffle(_DIRECTIONS) inside the `current_segment` loop will affect how the segment itself is built, but here it's okay because the order of adding to `current_segment` doesn't matter, only the final set of points. The impact is negligible. A better place to shuffle for single-hit targeting is in the loop where it is used. Although, for extending a detected segment, the order does not matter that much.

The current code shuffles `_DIRECTIONS` for each point in the segment scan, this might be slightly overdoing it but won't hurt correctness. The actual target selection for single-hit segments uses `_DIRECTIONS` after they have been shuffled. This is fine. Okay, the shuffle within the inner loop is actually good for path exploration when building the segment.

*   Global state is fine for this context: one game, one agent.
*   Time complexity:

    Args:

               -1: Miss (fired here and hit water)
               1: Hit (fired here and hit a ship cell)

    Returns:

        next cell to fire at.
    """

    # This helps identify ships or parts of ships.
    all_hits = set()
    for r in range(10):
        for c in range(10):
            if board[r][c] == 1:
                all_hits.add((r, c))

    visited_for_segments = set()

        if (hr, hc) not in visited_for_segments:
            # Start a new segment search from an unvisited hit
            current_segment = []

            visited_for_segments.add((hr, hc))

                random.shuffle(_DIRECTIONS) 
                for dr, dc in _DIRECTIONS:
                    nr, nc = curr_r + dr, curr_c + dc
                    # Check bounds, if it's a hit, and not yet visited
                    if 0 <= nr < 10 and 0 <= nc < 10 and board[nr][nc] == 1 and (nr, nc) not in visited_for_segments:
                        visited_for_segments.add((nr, nc))
                        stack.append((nr, nc))

    scored_potential_shots = []

        current_segment_shots = []

        if segment_len == 1:

            r, c = segment[0]
            random.shuffle(_DIRECTIONS) # Shuffle again for randomness in choosing direction for isolated hits
            for dr, dc in _DIRECTIONS:

                # Try extending downwards
                if max_r + 1 < 10 and board[max_r + 1][c] == 0:
                    current_segment_shots.append((max_r + 1, c))
        
        # Add all potential shots from this segment, paired with its length as a score.
        for shot_coord in current_segment_shots:
            scored_potential_shots.append((segment_len, shot_coord))
            
    if scored_potential_shots:

        # If multiple shots have the same highest score, choose one randomly.
        scored_potential_shots.sort(key=lambda x: x[0], reverse=True)
        
        max_score = scored_potential_shots[0][0]
        top_shots = [s[1] for s in scored_potential_shots if s[0] == max_score]
